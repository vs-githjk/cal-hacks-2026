# Checkout implementation report

This branch now has a buyer-owned checkout adapter, strict Payment Protocol request screening, a signed Shield allow receipt, a durable MerchantSim attempt record, and an exact local no-charge retirement operation. The checkout accepts only an identity-bound transaction with the stored deal, AdvocateCard, mandate, and a genuine approved VoiceApproval (or a distinct, exact allowance authorization). It does not accept the market's typed approval row as a voice record or as an allowance authorization.

`agents.buyer.checkout.approve_offer(transaction, client, service, *, on_code, buyer_name='Vidyut')` validates the frozen transaction and derives the call reason from the canonical stored AdvocateCard. `on_code` must deliver the one-time code to the authenticated buyer screen bound to this buyer and session; callback failure stops before dialing. The adapter never logs, returns, or persists the code. It returns `VoiceResult`; the market caller persists its canonical record on the state connection's owner thread.

`agents.buyer.checkout.settle_offer(transaction, request_payment, merchant_sim, *, receipt, message_id, tap_private_key, merchant_url='https://merchant.sim.test/v1/charge', now=None)` serializes the exact protocol object once, checks amount/currency/payee/reference/deal and the deterministic request ID, signs those same bytes with TAP, and delegates only to the existing MerchantSim. `agents.payment.commit(req, transaction, now=None)` creates CommitPayment only after the matching saved result is `charged`, is labeled `SIM`, has the same mandate hash, and contains a real-shaped `pi_`/`ch_` reference. Its persisted settlement envelope binds the deterministic request id and SHA-256 of those exact serialized bytes, plus deal, buyer, amount, currency, payee, mandate and idempotency key; receipt contents/signatures are not persisted. The seller's CompletePayment remains an acknowledgement gate in market-owned code and cannot initiate a charge.

Voice approval checks now share `pay.approval.approved_voice_record_matches`. It binds the VoiceApproval ID, mandate ID/hash, exact amount and payee read-backs, and issue/decision timestamps. The call uses the shared 300-second `VOICE_CODE_TTL_SECONDS`; browser sessions keep their 120-second default. Decimal cents parsing rejects non-finite and extreme values before multiplication/conversion.
Business-time checks accept an injected aware UTC clock through `_bound_transaction`, `approve_offer`, `settle_offer`, `approve_in_chat`, and `agents.payment._authorized`; typed approval session issue/decision and VoiceApproval matching use the same source. Async typed-code wait deadlines remain based on the monotonic event-loop clock. Callers that inject a clock must pass a callable returning aware UTC datetimes.

`NonceStore.start_payment_attempt` atomically writes the immutable submitted attempt, records the existing mandate idempotency key, and consumes the mandate nonce before network submission. Attempt, nonce, and the attempt-to-nonce binding share the existing private SQLite store. Owner startup explicitly calls `recover_submitted_attempts()` once; constructing a MerchantSim never triggers recovery or a retry. Only identity-bound local `reconcile(deal_id, buyer_id, mandate_hash)` can retry an identical uncertain attempt, and only while the original mandate is still live. Expired uncertain attempts stay uncertain; cached charged results are returned without another charger call.

For cancellation before submission, `NonceStore.retirement_attempt(...)` builds the immutable binding and `req:` message ID from the exact RequestPayment bytes. `retire_unsubmitted_attempt(attempt, mandate_nonce) -> bool` atomically records only `phase='refused', reason='retired_before_submission'` and consumes that nonce. It returns `True` only for that exact persisted marker and its bound nonce, including an identical repeated retirement. It returns `False` for submitted, reconciling, uncertain, charged, mismatched, or other refused attempts. Generic MerchantSim refusal is not no-charge proof. Market was given this exact helper/callback contract for its trusted reservation-resolution path.

Shield and MerchantSim reject duplicate JSON keys. The accepted request has one canonical positive two-decimal USD Stripe fund and must match the exact mandate and stored recipient. Checkout fails closed when TAP or Shield receipt keyrings are absent. No compatibility bypass was added for the demo or production agents.

The intended Ops database is `agents/.state/state.sqlite3`, shared with `NonceStore` under the protected `.state` directory. This worker checkout still contains the older Ops state base with `agents/.state.sqlite3`; root has integrated Ops commits `af8ec3c` and `40721ee` separately and will reconcile after this adapter commit.

# 0310 C CRS: SIM only by explicit label, signed cache (#449 RT-25)
`agents/crs.py`: a payee is a SIM seller (exempt, not checked) only when the operator's `CRS_TEST_IDENTITIES_PATH` file has an entry for it with `seller_type` `sim` or `individual`. No file, no entry, or any other type is a business payee; with CRS not configured for it, `check_payee` returns a `NOT_CONFIGURED` CrsCheck and `pay.crs_gate.payee_ok` holds it (`crs_not_configured`). `eligible()` no longer passes an unconfigured seller. `payee_status` gains state `not_configured`.
The cache `.cache/crs-signals.json`: each entry carries `mac`, an HMAC-SHA256 over supplier key, persona, signal and reason, keyed by env `CRS_CACHE_SECRET` (16+ characters). `crs.sign_entry` / `crs.entry_verified`. Without the secret, or with a missing or wrong tag, a cached signal is ignored when the sandbox is down; `demo/crs_relay.py` and `agents/pulse/orchestrator.py read_crs` skip unsigned entries too. The existing untagged cache is ignored until a fresh `agents/crs.py --live` run with the secret set.
Operator step: add `{"seller_type": "sim"}` entries for every id a gate looks up (`seller_N` for the buyer agent, the market seller id for `demo/bridge.py`, the build's `sellerId`s for `demo/build.py`), or nothing is ordered from or paid to those sellers.

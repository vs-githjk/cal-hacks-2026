# 2255 C CRS status per build payee in the dry run (#398)
`python3 demo/build.py --dry-run` now ends with a "CRS per payee" section: one line per distinct champion seller (sellerId, the key the private profile file uses), tagged with the seller's own origin. Each line is one of: `no CRS profile: <reason>` (no profile file, no entry for the seller, or an individual profile), `business CRS profile (Pxx), not checked` (a dry run makes no CRS call), `business CRS profile (Pxx), CRS band <band>, recorded <checked_at>` (a fresh cached result for the same persona; never LIVE, and anything but verified_stable says the payee gate would hold), or `CRS unknown` (the profile file is unreadable; never shown as no profile).
New `agents/crs.py payee_status(supplier_id, now)`: local files only. It never logs in, because a failed login locks the shared sandbox account. `demo/bridge.py crs_module()` is the one loader for agents/crs.py (default_crs_check uses it too), so there is one login latch and one payee cache.
Operator step, not in git: to give the build's SIM sellers CRS identities, add `gadget-grove`, `fair-price-pc` and `bargain-bin` entries to the private `CRS_TEST_IDENTITIES_PATH` file, each with an approved `persona_ref` and its exact official request body. Which persona goes to which seller is Vidyut's call: P12 returns not_verified, so a P12 seller that wins a part holds the payee gate and stops the live build.
Affects: dry-run output only. BuildView, the deal card and the live payee gate are unchanged.

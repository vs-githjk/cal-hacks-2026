# Lane A: sourced MIRROR terms and independent claim checks

`agents/sellers/policy.py` keeps the three registered seller IDs and SIM catalog. A seller's MIRROR assignment names the merchant printed on the listing; the seller agent remains the sealed-bid sender. A MIRROR line is omitted unless the captured listing is in stock, condition and model are known, and dated operator inputs provide both a nonnegative floor and flat shipping with provenance. Unknown terms never become zero or a guessed floor. Multiple MIRROR alternatives are accepted only for one SKU and one seller of record in one snapshot. The exact 5070 Ti request is preserved as `rtx 5070 ti`.

For a MIRROR `BidLine`, `unit_price` is the listing price used for the floor comparison; `shipping` is a flat line charge applied once at the Need quantity. The bid's `total_landed_price` sums the selected line's `unit_price * quantity + shipping`. SIM basket shipping is allocated once to the first carried line, with explicit zero on other lines. The market scorer must use each line's shipping when selecting allowed-condition alternatives, checking the cap, and ranking; its present scorer only uses `unit_price * quantity`, so MIRROR ordering is not production-correct until that consumer is updated. Do not infer shipping from `total_landed_price` or charge it twice.

`AdvocateCard.claim_checks` carries up to nine bounded normalized condition checks: `{bid_id, line_index, listing_id, sku_spec, field, value, result, evidence_url, evidence_hash, checked_at, source, origin}`. These are the same check results used to determine the card's condition warning and can be relayed to market `attach_claim_check` as `bidId`, `claim` (`condition:<value>`), `check`, `evidenceUrl`, and `origin`. It contains no fetched page prose. SIM fixture `page_condition` remains a labelled deterministic control; LIVE and MIRROR condition claims use the independent claim checker, where `false` vetoes and `unverified` cautions. Missing claims and checks do not count as verified.

The live handler runs deterministic Shield screening, bounded checks (nine claims, three concurrent, 1.5-second guarded fetch, five-second wall cap), deterministic veto/reason selection, then bounded Claude explanation. Claude receives only card recommendation, closed rule ID/summary, and a URL stripped to origin/path; it cannot alter warnings, recommendation, or spoken reason. The repository's current seller handler already uses model `claude-haiku-5-5`; the advocate reuses that existing model ID. SDK introspection confirmed installed Anthropic SDK structured JSON schema output support. Missing credentials, timeout, invalid output, or SDK errors return the sourced deterministic template fallback.

Evidence limits remain explicit: captured Best Buy stock is absent and floor/shipping inputs are empty, so no default MIRROR seller bid is currently eligible. The captured baseline is about 50 seconds from one source, not three days or a market consensus. No live retailer, claim-check, recall, seller-record, or paid model calls were run in tests. The market shipping scorer and lifecycle relay remain integration hooks for the root/market owner.

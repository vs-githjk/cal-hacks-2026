# 0310 C Edge auth: buyer REST chat, Shield bearer, production-mode peer seeds (#449 RT-26, RT-27)
- Buyer `/chat` (GET and POST, port 8001) answers only a loopback peer with no `X-Forwarded-*`, `Forwarded` or `X-Real-IP` header and no `Origin` header (`agents/buyer/rest_gate.py`, installed in `buyer_agent.py` main). Optional `BUYER_REST_TOKEN` also requires `Authorization: Bearer <token>`; `buyer/web_chat.py` sends it.
- `shield.api.create_app(api_token=...)` / env `SHIELD_API_TOKEN`: set, every route but `GET /v1/shield/health` needs `Authorization: Bearer <token>` (401 with `WWW-Authenticate: Bearer`). `common.screen()` sends it. `shield.product` builds its core with no token (it has its own API keys).
- `common.require_peer_seeds(role)`: in mailbox mode a buyer, advocate or seller whose peer seed is missing or `*-dev` raises at startup. `common.trusted_sellers()` and `common.seller_address()`: in mailbox mode a seller on a public dev seed is not a trusted sender (buyer bids and orders, Market Pulse records).

# 2320 C Hosted dead ends: /sell and /hyphenate on the deployed site (#398, intentionality item 1)
On the hosted site, `/sell` and `/hyphenate` said "offline, start python3 ..." and their browsers fetched 127.0.0.1 (ports 8791 and 8789), which failed with CORS and console errors. Now a page decides in the browser whether its API is reachable: `web/src/lib/url.ts reachableFrom(api, pageHost)` is null for a loopback API seen from a page that is not itself on loopback (the same rule as `feedBase`), and `web/src/lib/useApiBase.ts` gives `{ready, base, local}` without a hydration mismatch. When `local`, the page fetches nothing and shows a recorded SIM snapshot under `RecordedBanner` ("Recorded snapshot (SIM), captured <UTC time>. The live version runs locally." plus a README link): `web/src/lib/fixtures/hyphenate-recorded.json` (hyphenate/api.py, story=moment, all 8 reads the page makes) and `sell-recorded.json` (seller_kit/api.py: no shops, the 4 labelled SIM sample needs). /sell hides its form there (no dead button) and says why with `RunsLocally`. On localhost both pages work exactly as before.
Affects: web/src/app/sell/page.tsx, web/src/app/hyphenate/page.tsx, web/src/components/hyphenate.tsx (new state "local"), web/src/components/ui.tsx (RunsLocally, RecordedBanner, README_URL), web/src/lib/recorded.ts (the label). Screenshots before and after at 390 and 1440 are in docs/changes/shots/398-hosted-dead-ends/.

Paste 00-shared.md first, then this.

You own shield/, pay/ and sim/. Goal: money moves safely, agents stay honest, and the store's books balance.

Tasks in order:
1. Bazaar Shield API (FastAPI): POST /screen (planted instructions, scam patterns, policy breaks in an agent message; allow, quarantine or block with reasons), POST /verify-agent (agent identity: Visa Trusted Agent Protocol style signatures, CRS for the human or business behind it), POST /check-claim (calls Lane C's checker). Test-first with a corpus of attacks and legitimate messages that merely quote instructions. Publish a short API doc page. This is the Armadin pitch: Armadin (Kevin Mandia's company) builds AI red-teaming with an agentic attacker swarm, which is exactly the wind tunnel.
2. Checkout and Visa: Fetch.ai's Payment Protocol supports Stripe and Link today, not Visa directly. So: (a) money moves through the Payment Protocol over Stripe test mode (or Link), charging a Visa test card (Stripe's 4242 4242 4242 4242 is a Visa), only after the approval card and within the limit; (b) implement Visa's Trusted Agent Protocol for real: sign every agent request to a store with HTTP Message Signatures (Visa and Cloudflare open spec, Oct 2025), verify them at the store and in Shield, and show 'signature verified' in the UI; (c) put a Visa Intelligent Commerce adapter (tokenized agent credentials; github.com/visa/ai, sandbox.mcp.visa.com, needs X-Pay credentials) behind the same payment interface, and swap it in only if Visa's booth grants access. The README states exactly which part is live and which is an adapter.
3. CRS: sandbox at calhacks.crscreditapi.com (and the CRS MCP server, npm @crscreditapi/crs-calhacks-mcp-server), provided test identities only. Two uses: consented affordability for the advocate (open payment plans, utilisation), and synthetic shoppers plus fraud signals for the wind tunnel ("Most Unexpected Use", "Identity and Fraud").
4. Wind tunnel: generate hundreds of simulated shoppers (most on small cheap models, about 20 full agents) with goals, budgets and CRS identities, plus hostile agents (planted instructions in reviews, fake discount codes, refund fraud). Run them against a store's agent and catalog mirror; output conversion, where shoppers stalled, which attacks landed, and fixes. Every hostile message becomes a Shield test case.
5. Store finance desk (Hyphenate track, stretch after the demo path): double-entry ledger for each order, discount, refund and fee; discounts above a set limit need a human controller's approval (the bidding agent cannot approve its own); reconcile against Visa settlement and flag any difference with the reason.
Done when: a liar is caught live with a reason, a Stripe test-mode charge on a Visa card completes only after approval with the agent's Trusted Agent Protocol signature verified, and Shield's catch rate on the attack corpus is in the README.
